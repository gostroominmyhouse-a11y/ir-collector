# IR-Collector

Скрипт на Python для первичного сбора данных (triage) на машине, где подозревается инцидент ИБ.
Он снимает состояние системы, ищет в логах неудачные входы, извлекает внешние IP-адреса
и проверяет их репутацию в [AbuseIPDB](https://www.abuseipdb.com/). Результаты складываются в одну
папку, а в конце считаются SHA-256 хэши всех файлов.

Работает на Linux, Windows и macOS (Python 3.9+).

## Что собирается

| Файл | Что внутри | Зачем это аналитику |
|---|---|---|
| `system_info.json` | хост, пользователь, ОС, время загрузки, активные сессии, сетевые интерфейсы | понять, с какой машины данные и кто на ней работает |
| `network_connections.txt` | все TCP/UDP-соединения: процесс, PID, локальный и удалённый адрес, статус | поиск связи с C2, бэкдоров на нестандартных портах |
| `processes.csv` | PID, PPID, имя, пользователь, путь, командная строка, время запуска | поиск вредоносных процессов; процессы из Temp/Downloads помечаются флагом |
| `failed_logins.txt` | строки логов с `Failed password`, `Logon Failure` и т.п., топ IP по числу попыток | обнаружение перебора паролей (brute force) |
| `system_log_export.txt` | экспорт событий 4625 (Windows) или journald auth (Linux) | на Windows нет текстовых логов входа, их приходится выгружать |
| `external_ips.txt` | уникальные внешние IP и где каждый из них встретился | список для ручной проверки, даже без API-ключа |
| `suspicious_ips.json` | результаты AbuseIPDB: score, страна, провайдер, Tor | базовый Threat Intel |
| `Summary_Report.txt` | краткая сводка по всем шагам | с этого файла начинают разбор |
| `hashes_sha256.txt` | SHA-256 собранных файлов | целостность доказательств (chain of custody) |
| `script_run.log` | подробный лог работы скрипта | видно, какие данные не удалось собрать и почему |

## Установка

```bash
git clone <repo-url> && cd Basic-IR-Collector
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
# Обычный запуск (лучше от root / Администратора, иначе часть данных будет скрыта)
sudo python3 triage_collector.py

# Демо на синтетических логах из папки sample_logs
python3 triage_collector.py --log-file sample_logs/auth.log --log-file sample_logs/windows_security_4625.txt

# Сохранить результаты на флешку, чтобы не писать на диск исследуемой машины
python3 triage_collector.py --output-base /media/IR_USB
```

Для проверки IP нужен бесплатный API-ключ AbuseIPDB (регистрация на сайте, 1000 запросов в сутки).
Его можно передать двумя способами:

```bash
export ABUSEIPDB_API_KEY="ваш_ключ"     # рекомендуется: ключ не попадёт в Git
# или прописать в config.json -> "abuseipdb_api_key"
```

Без ключа или без интернета скрипт не падает: он пропускает проверку, а список внешних IP
всё равно сохраняет в `external_ips.txt`.

Проверить, что собранные файлы не менялись: `sha256sum -c hashes_sha256.txt`
(на macOS `shasum -a 256 -c hashes_sha256.txt`).

## Как это устроено

Скрипт выполняет шаги по очереди, и каждый шаг обёрнут в `try/except`. Если один шаг упал,
остальные всё равно отработают: при реагировании на инцидент лучше собрать хоть что-то.

1. **Подготовка.** Создаётся папка `IR_Collected_Data_YYYYMMDD_HHMMSS`, настраивается логирование
   в консоль и в файл.
2. **Состояние системы.** Сначала собираются самые изменчивые данные, соединения и процессы,
   потом логи (порядок по RFC 3227). Если нет прав на чтение процесса, поле помечается
   `ACCESS_DENIED`, а сам процесс остаётся в списке.
3. **Логи.** Файлы читаются построчно и ищутся ключевые слова. На Windows события 4625
   выгружаются через PowerShell (`Get-WinEvent`), на Linux без `auth.log` используется `journalctl`.
4. **IP-адреса.** Регулярное выражение находит кандидатов, модуль `ipaddress` отсекает невалидные
   адреса и служебные диапазоны (10/8, 172.16/12, 192.168/16, 127/8, 169.254/16 и др.), а также
   собственные адреса машины. Оставшиеся адреса проверяются в AbuseIPDB.
5. **Отчёт.** Пишется `Summary_Report.txt` и файл с хэшами.

Настройки (пути к логам, ключевые слова, порог подозрительности, лимит проверок) хранятся
в `config.json`.

## Ограничения и идеи для развития

- Только IPv4 при поиске IP-адресов в тексте.
- Нет сбора автозагрузки (Run-ключи реестра, cron, systemd-юниты, LaunchAgents).
- Нет дампа памяти: для этого есть специализированные инструменты (WinPmem, LiME, AVML).
- Можно добавить проверку хэшей исполняемых файлов процессов в VirusTotal.
- Можно выгружать результаты в SIEM (JSON/Syslog).

## Важно

Запускайте скрипт только на системах, где у вас есть разрешение на сбор данных.
Логи в `sample_logs/` синтетические и сделаны для демонстрации. IP-адреса в них взяты из диапазона
выходных узлов Tor, который часто встречается в базах злоупотреблений.
